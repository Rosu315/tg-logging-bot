# TG Logging Bot

Telegram-бот, который сохраняет то, что собеседник забрал обратно: удалённые сообщения, изменённые сообщения и одноразовые медиа — плюс веб-вьюер, чтобы просматривать этот архив как экспорт переписки.

## О проекте

Telegram позволяет подключить бота к личному аккаунту через раздел «Автоматизация чатов» в
профиле. Подключённый так бот получает обновления аккаунта — в том числе
`deleted_business_messages` и `edited_business_message`, которых нет больше нигде на
платформе.

Этот бот слушает эти обновления и присылает результат вам в личный чат с ботом.
Собеседник удалил сообщение у двоих — вы получаете копию. Отредактировал — получаете
старую и новую версию. Медиа приходит настоящим файлом, а не скриншотом. Команда
`/backup` также открывает веб-версию всего архива в виде чата, с пометками у удалённых,
изменённых и одноразовых сообщений.

Бот работает на вашей машине. Ничего никуда не отправляется, кроме вашего же чата с вашим
же ботом.

> **Telegram Premium не нужен.** Раньше подключение ботов к аккаунту было премиум-функцией
> — больше нет.

## Возможности

- **🗑 Уведомления об удалении** — как только сообщение удаляют у двоих, сохранённая копия
  приходит вам: и текст, и вложение.
- **✏️ Уведомления об изменении** — старая и новая версия отредактированного сообщения
  рядом.
- **🔥 Сохранение одноразок** — ответьте на одноразовое фото, видео или голосовое **до**
  просмотра, и оно придёт вам обычным файлом.
- **⚙️ Раздел настроек** — каждый тип уведомлений переключается на
  `t.me/<ваш-бот>?start=settings`. Мешают уведомления об изменениях — отключите только их.
- **🌐 Русский и английский** интерфейс, переключается прямо в настройках.
- **🧹 Контроль хранения** — снимки живут `RETENTION_DAYS` дней, а `/purge` стирает всё
  сразу.
- **📦 Веб-бэкап** — `/backup` выдаёт короткоживущую подписанную ссылку на страницу,
  рендерящую весь архив как переписку, с пометками у удалённых/изменённых/одноразовых
  сообщений.

## Требования

- Python 3.10 или новее (либо Docker)
- Токен бота от [@BotFather](https://t.me/BotFather) с включённым **Business Mode**

## Установка

```bash
git clone https://github.com/Rosu315/tg-logging-bot.git
cd tg-logging-bot
python -m venv .venv && .venv\Scripts\activate    # Linux/macOS: source .venv/bin/activate
pip install -e .
copy .env.example .env                             # впишите токен в BOT_TOKEN
python -m tg_logging_bot
```

Через Docker:

```bash
cp .env.example .env
docker compose up -d
```

## Как пользоваться

### 1. Подготовьте бота

В [@BotFather](https://t.me/BotFather): `/mybots` → ваш бот → **Bot Settings** →
**Business Mode** → **Turn on**. Без этого аккаунт не найдёт бота в списке автоматизации.

### 2. Подключите его к аккаунту

1. Откройте свой профиль и нажмите **«Изм.»**
2. Найдите раздел **«Автоматизация чатов»**
3. Введите `@ваш_бот` и нажмите **«Добавить»**
4. Оставьте разрешение **читать сообщения** — без него бот не увидит удаления

Бот подтвердит подключение в личном чате. Если права на чтение нет, он прямо скажет об
этом, а не будет молча ничего не делать.

### 3. Работа

| Что нужно | Что сделать |
| --- | --- |
| Ловить удаления и правки | Ничего — работает сразу после подключения |
| Сохранить одноразку | Ответить на неё любым сообщением **до** просмотра |
| Отключить уведомление | `/settings` или ссылка `t.me/<ваш-бот>?start=settings` |
| Посмотреть архив как переписку | `/backup` |
| Посмотреть, что хранится | `/status` |
| Стереть всё сохранённое | `/purge` |

### Как выглядит уведомление

```
🗑 Удалённое сообщение

От: Полина (@polina)
Чат: Полина
Время: 08.01.2026 14:13
Вложение: 🖼 фото

> Любое сообщение
```

Само фото приложено к этому сообщению.

## Настройка

Все параметры — переменные окружения из `.env` (см. [`.env.example`](.env.example)).

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | — | Обязательно. Токен от @BotFather |
| `DB_PATH` | `data/bot.db` | Файл SQLite со снимками |
| `MEDIA_DIR` | `data/media` | Куда складывать кэш медиа |
| `CACHE_MEDIA` | `false` | Скачивать медиа сразу, а не полагаться на `file_id` |
| `MAX_CACHE_FILE_MB` | `20` | Не кэшировать файлы больше этого размера (лимит Bot API) |
| `RETENTION_DAYS` | `14` | Через сколько дней снимки удаляются; `0` — не удалять |
| `CLEANUP_INTERVAL_MINUTES` | `60` | Как часто работает уборщик |
| `LOG_LEVEL` | `INFO` | `DEBUG` при отправке баг-репорта |
| `WEB_HOST` | `127.0.0.1` | Адрес для веб-вьювера `/backup` — держите на loopback, наружу через туннель |
| `WEB_PORT` | `8088` | Порт веб-вьювера `/backup` |
| `BACKUP_PUBLIC_URL` | — | Публичный HTTPS-адрес, под который собирается ссылка `/backup`. Без него команда не работает |
| `BACKUP_LINK_TTL_MINUTES` | `30` | Сколько минут действительна ссылка `/backup` |

**Про `CACHE_MEDIA`.** По умолчанию бот хранит только `file_id` и пересылает файл с
серверов Telegram в момент удаления — дёшево и почти всегда работает. `CACHE_MEDIA=true`
скачивает каждый файл сразу: это спасает, если Telegram отозвал ссылку, но стоит места на
диске и трафика.

## Как это устроено

Обновление об удалении содержит **только идентификаторы** — ни текста, ни файлов:

```json
{ "business_connection_id": "...", "chat": { ... }, "message_ids": [101, 102] }
```

Поэтому содержимое нужно сохранить заранее. Каждое сообщение, прошедшее через
подключение, кладётся снимком в SQLite, а при удалении находится по идентификатору и
отдаётся вам — при этом строка помечается `deleted_at`, а не стирается, так что `/backup`
может показать её и позже. Правки так же хранят предыдущий текст (`prev_text`).

```
business_message         ──▶  capture.py        ──▶  таблица snapshots
edited_business_message  ──▶  старый снимок + новое сообщение ──▶  карточка правки + prev_text
deleted_business_messages──▶  помечает deleted_at              ──▶  карточка удаления
/backup                   ──▶  подписанный токен  ──▶  web.py рендерит архив
```

| Модуль | За что отвечает |
| --- | --- |
| `handlers/business.py` | Четыре бизнес-обновления |
| `handlers/settings.py` | Экран настроек и deep-link `?start=settings` |
| `handlers/backup.py` | Команда `/backup` — выдаёт подписанную ссылку |
| `capture.py` | Сообщение → снимок, с опциональной загрузкой медиа |
| `storage.py` | SQLite: подключения, настройки, снимки, собеседники |
| `media.py` | Извлечение медиа, детект одноразок, отправка обратно |
| `render.py` | Карточки уведомлений |
| `janitor.py` | Очистка по сроку хранения |
| `tokens.py` | Подписанные токены ссылок `/backup` |
| `web.py` | Веб-вьювер `/backup` (aiohttp, тот же процесс) |

Детект одноразок сделан с запасом: в Bot API нет задокументированного стабильного флага
самоуничтожающихся медиа, поэтому `media.is_one_time()` проверяет все известные написания
(`view_once`, `ttl_seconds`, …) и на сообщении, и на самом медиа, читая их из
`model_extra` aiogram — так новое имя поля заработает без обновления библиотеки. Если
Telegram не прислал никакой пометки, решение принимает настройка «Сохранять любое медиа в
ответе».
